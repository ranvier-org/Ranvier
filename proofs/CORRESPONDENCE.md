# Correspondence

Each row maps a symbol of the model to the F# in `src/Ranvier/Core.fs` (pinned at commit
`d701e6c5`), and lists every simplification with its reason.

| Model symbol | Core.fs symbol | Simplification and reason |
|---|---|---|
| `nid` | node identity | `nat`; node ids are opaque. |
| `oid` | owner identity | `nat`; owner ids are opaque. |
| `val` | node value | `Z`; the model fixes one value type. |
| `fresh` | node freshness state | `Clean`, `Check`, `Dirty`; ordered `Clean <= Check <= Dirty`. |

## Reference tier

The reference tier defines meaning for any engine, so it has no Core.fs symbol for marks, freshness
or the queue. Task 12 relates it to the engine. These rows record its fragment and where its
choices come from.

| Model symbol | Core.fs symbol | Simplification and reason |
|---|---|---|
| `val := Z` | generic `'T` | Unbounded integers against Core.fs's fixed-width integers in user bodies. Overflow is outside the tier, so a body whose arithmetic wraps in F# has a different value here. |
| `rprog` | a graph built by user code | A static node set. A program whose effect creates or disposes nodes is outside the fragment and keeps only the general engine theorems. Author's call, from the plan. |
| `rmemos`, `well_behaved_memo` | `Memo` | No previous-value argument, ownership, cleanups, writes, disposal, effect creation or untracked read. A memo has no comparer here: cutoff compares outcomes by equality, as `CmpEq`. `CmpNever` and `CmpThrows` are outside the fragment. |
| `memos_acyclic` | none | A rank that decreases along every read, for every answer the reads can give. A cycle or self-read that some answers would reach is outside the fragment, whether or not the program's signals reach it. |
| `reffects`, `well_behaved_effect` | `Effect` | Bodies use `CRet`, `CThrow`, `CLet`, `CIf`, `CRead`, `CTryRead`, `CReadU`, `CWrite`, `CCleanup`, `CLog`, `CBatch`, and no `EPrev`: an effect has no previous value. `rwf` rejects `CSignal`, `CMemo`, `CEffect`, `CDispose`. |
| `exec` on `CIf` | `if` in a body | A zero condition selects the else branch. |
| `exec` on `CTryRead` | `TryValue` | `ok` binds 1 or 0, and `x` binds the value or the failure's identity. |
| `exec` on `CRead` | `Value` | A failed memo ends the body with its failure, and the read counts as tracked. |
| `exec` on `CBatch` | `RunBatch` | Sequences its parts. Writes apply immediately, and a flush cannot nest in a round. |
| `eval_expr` on `EDiv`, `div_zero_failure` | `DivideByZeroException`, `Effect.RunBody` | A zero divisor is the failure `div_zero_failure`, the body's outcome, as `RunBody` records the exception. Later effects run. The identity is one fixed value, so it has the difference in the `Fail f` row: F# throws a new exception per zero divisor, so a memo that fails this way on consecutive recomputes has moved in F# and has not moved here. `CThrow (-1)` denotes the same failure. |
| `Fail f`, `outcome` in read comparison | `Failure.Moved`, `Graph.FailureOf` | `f` denotes an exception instance. Outcomes compare by `f`, as `Moved` compares instances by reference. `CThrow f` is a body throwing the same stored instance on every evaluation, so an unmoved failure wakes nothing. A body throwing a new exception per recompute has no fixed `CThrow` form: `FailureOf` allocates a new `Failure`, the failure has moved and wakes readers, whereas `CThrow 7` on re-evaluation is the same outcome and wakes nothing. Tasks 4 and 12 rely on this row. |
| `EvRun` | `Effect.RunBody`, `runs` | Emitted once per effect run, after its cleanups. Memo-body evaluation is not an event, so the observable number of runs is the number of effect runs. A memo's run count belongs to the engine. |
| `EvLog` in a memo | a user side effect in a memo body | Discarded in this tier: its count would be a memo's run count. |
| `run_cleanups` | `Graph.Discharge`, `Owner.DisposeScope` | Newest first, before the body, with reads untracked. On a re-run, a cleanup registered by a cleanup joins the new scope, as `Owner.AddCleanup` does. A failed cleanup ends only itself and emits `EvFail n f`. In F# it goes through `RecordError` to `Root.Errors` (Core.fs 1085), which names no effect, whereas `EvFail` here carries `n`, so the differential check has no node to compare for these. Whether that failure then escapes the flush is engine behaviour, examined by scenario `S09b`. |
| `run_effect` on a failed body, `EvFail` | `Effect.RunBody`, `FailureOf` | `RunBody` records the failure on the effect's own `failure` field (Core.fs 4871), cleared at the start of each run (4840), and `run_effect` emits `EvFail n f` after the body's events. The next run clears the field, so the differential check has to read a body failure before then. A read of a failed memo fails the reader with the memo's failure. A memo's own failure has no event, since its evaluation count belongs to the engine. Later effects and later rounds run, and the reads and cleanups reached are kept. |
| `RDispose`, `apply_dispose` on an effect, `EvDispose` | `Effect.Dispose`, `Graph.Retire` | Host disposal only: disposal from inside an effect is outside this tier. Applies in batch order, before the batch's settling. Emits the pending cleanups, then `EvDispose`. `Tracer.NodeDispose` fires before the cleanups in F#, and the tracer is outside the model. The effect's entry is removed, so it has no reads and no later round runs it. A cleanup's writes apply, and wake readers in the settling that follows. |
| `bretired`, `exec` on `CCleanup` during disposal | `Owner.AddCleanup`, `Owner.RunLate` | On a disposed scope a registered cleanup runs at once, inline, and an exception is recorded. `exec` runs it at once and emits `EvCleanup`, and `EvFail` on failure, with the `Root.Errors` mapping of the `run_cleanups` row. |
| `RRead`, `EvHostRead`, `host_read` | `Signal.Value`, `Memo.TryValue` outside a computation | Answers at its position in the batch over the current signals, and a disposed memo answers from `rs_frozen`. A failed memo gives `EvHostRead n (Fail f)`, as `TryValue` gives `Failed`, and leaves the batch running. A host read wakes nothing and registers no dependency. A read of an effect or unknown node is stuck: an effect has no value. A memo read and then disposed keeps the value the read answered, as in F#, where the read pulls the memo: `host_read_then_dispose_memo`. |
| `apply_dispose` on a memo, `rs_frozen` | `Memo.Dispose`, `Memo.EnsureCurrent` | A disposed memo answers reads with its last value, and a failed one keeps its failure. The last value is the memo's value over the signals current at the disposal's position in the batch, by the owner's ruling. This matches F# for a memo that is clean at its disposal. It differs for a memo whose sources moved with no pull before the disposal: F# keeps the value it last computed, or the type's default if it never ran. That includes a write earlier in the batch to a memo with a live reader, which F# leaves unpulled. See `Suspected` in `BUGS.md`. Emits `EvDispose`. |
| `apply_dispose` when disposed already | `if not disposed` in `Dispose` | Idempotent: no event. |
| `RDispose` of a signal or unknown node | none | Stuck. `Signal` has no `Dispose` in Core.fs. |
| `run_all_reads` | none | Every read of a run in order, tracked and untracked, cleanups included. `redundant` compares it. The run set uses the tracked `run_reads` only. |
| `computed_from_snapshot` | closures in cleanups | The inputs are one signal snapshot, the disposed memos' values, and the captured environments of the cleanups the run ran. It also covers disposal records. A captured environment comes from the run that registered the cleanup, so a cleanup can log a value from an earlier snapshot, as an F# closure does: `cleanups_first`. Every read of the run answers from the one snapshot. |
| `rruns` initial round | `Effect.Start` | The history starts with one round in which every effect runs, in `effect_order`'s order. |
| `run_set`, `settle` | `RunFlush` | A round's run set comes from a snapshot: each effect's last-run tracked reads compared with the graph at the round's start. `CReadU` reads wake nothing. Writes by an effect apply immediately, so a later effect of the round reads them, and effects they wake run in the next round unless their last-run reads are already current. |
| `effect_order`, `rs_round` | the observer positions and queue | A parameter of the tier, indexed by the round's position in the whole history and valid when it permutes each round's effects. The initial round has index 0, and a settling with an empty run set takes no index. For a fixed program and history this expresses any order an engine chooses per flush. Task 12 characterises the engine's order. |
| `obs_full`, `obs_settled` | none | What an engine must preserve. `obs_settled` keeps, per node, the logs and failures since its last `EvRun`, including disposal cleanups' logs, the distinct failures of its history, and whether it is disposed, and for the whole trace every host read in order. Run counts, effect interleaving, and the logs of superseded runs and their cleanups are unobserved. |
| `refines`, `engine_answers` | none | Over any engine, with no import from `Pure/`. `refines` takes one valid order per history, compares every batch prefix, and requires each prefix's engine trace to be a prefix of the whole trace. `engine_answers`, over a fuel-indexed engine, is the converse obligation: some fuel gives a trace whenever the reference settles under every valid order. An engine proof owes both. |
| `fuel` | none | Bounds the rounds of each settling. A flush that keeps waking effects has no reference meaning: `rtrace` returns `None`, and the spec states flush theorems conditionally on a returned flush. |
| `None` from `exec` | none | A stuck body: an unbound variable, a negative node id, a read of an unknown node or an effect, a write to a non-signal. These have no F# counterpart, since F# bodies hold variables by scope and nodes by reference. A zero divisor is a failure, not a stuck body. |

## Observer sets and source lists

| Model symbol | Core.fs symbol | Simplification and reason |
|---|---|---|
| `scan_limit` | `EdgeHandle.ScanLimit` (141) | 8. |
| `obs`, `oitems`, `olatest` | `ObserverSet`: `items`, `count`, `latest` (195-212) | A list holds what `items[0..count-1]` holds, so capacity, growth and blanking are absent. Fable's separate `slots` array is one pair here. Arrays and blanking return in the heap tier. |
| `obs_add` | `ObserverSet.Add` (247-264) | Counters and tracer omitted. |
| `obs_try_add`, `tried` | `ObserverSet.TryAdd` (270-290), `EdgeHandle.Unlinked`, `Unknown` | The negative integer answers are constructors. The handle hint and the scan limit are kept, since they decide the answer. |
| `obs_remove_at` | `ObserverSet.RemoveAt` (301-357) | `None` is the `InvalidOperationException`. A negative handle (a no-op in F#) has no form: `trimFrom` tests `handle >= 0` first, and a slot's `None` is that test. The direct callers in the row below are outside `remove_edge`. The result carries the `MovedIn` call as a notice, applied by `remove_edge`. As in F#, `olatest` follows a moved last observer, and stays past the end when the last observer is removed. |
| `walk`, `walk_mut`, `apply_muts` | `NotifyDirty`, `NotifyDirtyExcept`, `NotifyCheck` (372-428) | The natural is `i + 1`, so the F# `i = -1` is 0, and `walk_end` covers both loop exits. The mutations over-approximate a `Mark*` call: `WAdd` adds unconditionally and `WRemove` is any successful removal, at any visit, whether or not a mark can do either. `walk_visits_added_observer` depends on that over-approximation, and Task 6's `mark_preserves_edges` narrows it. The skip in `NotifyDirtyExcept` is not modelled: it omits a mark, and the position sequence is the same. Marks belong to Task 6. |
| `held_once`, `mut_points`, `observers_once`, `ew_point` | "Each observer is held at most once" (190) | `walk_covers` takes `held_once` at every single mutation, not only between visits. A single `obs_remove_at` ends in the observer set of the next `trim_loop` world, since the rest of a step changes only slots, and `sl_link` makes a single `obs_add`, so `ew_point` covers every set the operations pass through. A trim runs no user code, so one trim at a time is in progress. |
| `src`, `sslots`, `scursor` | `SourceList`: `first`, `firstHandle`, `rest`, `count`, `cursor` (540-570) | One list for the `first`/`rest` split, which is a space optimisation. `None` is `EdgeHandle.Unlinked`. |
| `EdgeWorld`, `obs_of`, `src_of` | a source's `observers`, a computation's `sources` | Maps by node id for object references. An absent node has an empty set or list, as a signal's `observers` is created on first add (3768-3780). |
| `sl_begin`, `sl_end`, `sl_clear` | `BeginRun`, `EndRun`, `Clear` (722, 803, 811) | Tracer omitted. |
| `sl_moved_in`, `set_handle` | `SourceList.MovedIn`, `setHandle` (599, 715) | A slot past the list is unchanged. F#'s write there lands in a blank array cell, and a coherent world reaches neither. |
| `sl_trim`, `trim_loop`, `sl_remove_slot` | `trimFrom` (658-694) | Each handle is read when its slot is reached, and the slot's handle is blanked after its removal. The source reference is kept until the slots are truncated at the end, since only the handle is read again. `held <- null` has no counterpart: see `sl_link`. The comment at Core.fs 662, "a removal can move this list's later edges", overstates: `trim_every_removal` shows a removal moves only other computations' edges, under `slots_unique`. |
| `sl_add`, `sl_link`, `sl_append` | `Add`, `Append` (729-796) | Slot 0 uses `obs_add`, as line 744 does, and later slots use `obs_try_add`, then `holds` on `TUnknown`. `holds` and `held` are membership in the slots. The heap tier abstracts `held` too, so no tier checks the `RefIndex` life cycle (573-576, 643-653, 659-660, 777-778). It was read and is correct: a reference-keyed map (`Platform.fs:671-680`, and a JS `Map` at 652-667) with -1 for a miss, built over the slots before `until`, extended by every append, dropped by every trim. The `first`/`rest` branch of `Append` has no other difference. |
| `edge_match`, `first_owns`, `ew_wf`, `ew_reachable` | the remarks at 530-531 | Invariants, with no F# symbol. `ew_reachable` lets every node interleave `sl_begin`, `sl_add`, `sl_end` and `sl_clear` freely, which covers the nested run of Review Focus 2. `sl_moved_in` is not a step, since it occurs only inside a removal. |
| `ew_reachable`'s boundary | `Binding` (`Bindings.fs:51, 105`), `FoldReads` (`Combinators.fs:669, 686`), `FoldRow` (`Combinators.fs:886, 944, 1047`), `ValueRow` (`ValueReaders.fs:72, 100`), `ForwardingEdge` (`Projections.fs:676, 688`) | These call `AddObserver` and `RemoveObserverAt` directly. They share observer sets with `SourceList` computations, set `olatest` and are moved by swap-removal, and no `ew_reachable` step creates them. Each is simulated by a node of its own, whose `sl_add` is the add and whose `sl_clear` is the removal, and each holds a distinct observer. `Binding` links once, in `Start`. `FoldReads.AddSource` is guarded by a reference `HashSet` and clears in slot order, its slots standing for a list with a cursor at its end. A `FoldRow` or `ValueRow` is constructed per entry and linked once. A `ForwardingEdge` is per entry, with add and remove guarded by `Watched` (`Projections.fs:668-669, 759-761`). A slot above 0 in `sl_add` reaches `obs_add` through `obs_try_add`, with the same result, since the observer is not held. This is an argument from reading, and no theorem covers these sites. Forwarders such as `Combinators.fs:1062` delegate and are no sites. |

## Graph state and edge coherence

| Model symbol | Core.fs symbol | Simplification and reason |
|---|---|---|
| `kind` | `Signal` (3732), `Memo` (4043), `Effect` (4622) | `AsyncSource`, `AsyncMemo`, `EffectOn` and the node types of other files are outside the model, since the command language creates none of them. |
| `status` | `Status` (`Types.fs:10`) | One constructor per stored value, since a `Signal`, `Memo` or `Effect` stores one flag at a time. `Pending ||| Uninitialized` occurs only on `AsyncSource` (3897). `Status.Stale` is computed from freshness by `Staleness.ofFreshness`, as `n_fresh` here. `StPending` follows a `NotReadyException` (4258, 4865), which needs an async source, so no program of the command language reaches it. |
| `link`, `l_child`, `l_gen`, `l_acquired` | `OwnerLink` (855-876), `IOwned` | `None` is `Generation = -1`. `Prev` and `Next` are positions in `o_children`. Generations are unbounded, so the wrap at 1145 is absent: reaching it takes 2^31 teardowns of one owner. `l_child` is a node: the command language's only `AttachLinked` callers are `Memo` (4162) and `Effect` (4709). `Owner` children come from `RunRoot` (2567), `Combinators.fs:1126` and `Projections.fs:2063, 2105`, `Owner.Attach` wraps an `IDisposable` (996), and the other callers are node types outside the model. F# shares one mutable `OwnerLink` between the owner's list and the holder, and the model holds value copies. The copies are safe: `Unlink` (1053) is the only write to a joined link's `Generation`, every holder clears its link right after `Detach` (4386-4387, 4897-4898) or before `Dispose` in `Release` (4723), and `l_gen` with `l_acquired` identify an entry, since `acquisitions` counts up within a generation and resets only when the generation changes (1145-1146). |
| `ownerS` | `Owner` (897-1250) | `o_children` is `head` to `tail`. `firstCleanup` and `cleanups` are one list, a space optimisation. `o_cleanup_envs` is the closure environment an F# cleanup captures, added beside the plan's `o_cleanups : list cmd`, since a `cmd` has free variables. `o_cleanup_order` is `firstOrder` and `cleanupOrder`. The three cleanup lists have one writer and one reader helper from Task 7, and `engine_inv` holds them at equal lengths. `o_cleanups` is stored earliest first, as the F# lists are, and teardown runs it from the end. `bclean` stores newest first. `o_sink` is `sink`, and `o_errors` is `errors`. `parentLink`, `SetParent` and the `:? RootScope` tests (1026, 1213) have no field: in `Core.fs` only `RunRoot` (2566-2567) creates a `RootScope` or calls `SetParent`, the other `SetParent` callers are `Combinators.fs:1126` and `Projections.fs:2063, 2105`, and the command language reaches none of them. A computation's scope is `new Owner (graph.Root)`, which no parent holds (4443, 4915). `IDisposable`, the tracer and `RANVIER_TRACE` state are omitted. |
| `node` | fields of `Memo` (4063-4096) and `Effect` (4635-4672) | One record for three kinds, with fields a kind does not use left unread. `n_failure` denotes the exception instance, as in the `Fail f` row. `n_body`, `n_env` are the closure. `n_scope` is `scope`, `n_mode` is `mode`, and `n_cmp` is the comparer. `adopted`, `publishes` and `pendingSources` belong to features outside the command language. Task 7 adds `n_link` for `link` (4081, 4648). |
| `flags`, `current_flags` | none | The model's switches for Task 11's witnesses. `Core.fs` is `current_flags`. |
| `state` | `Graph` fields (2078-2265) | `g_queue` is `queue[0..queueCount-1]` and `g_head` is `queueHead`. `g_flushing`, `g_owed`, `g_batch`, `g_pull`, `g_current`, `g_owner`, `g_next` are `flushing`, `flushOwed`, `batchDepth`, `pullDepth`, `current`, `currentOwner`, `nextId`. `g_untracked` is `untrackedInBody`. `g_trace` and `g_running` are ghost state. `pullAmbient`, `pullHeld`, the inbox and the dispatcher serve hosting and threads, and the model has one graph on one thread. `detachedDepth` is read only by `Running` (2392), which selects the ambient graph (2380) and journal admission (2409), and the journal is absent too. `untrackedHost` is unreachable from the command language: it is read only when `currentOwner` and `current` are both null (2524-2547), which takes a node or cleanup created directly inside an `untrack` block, `CReadU`'s block holds one read, a body it pulls runs under `RunHosted`, which sets `current` (3467), and a teardown runs under `Detached`, which sets `currentOwner` (3390). `lastRaised` (2107) selects which `Failure` a run records, and so only its `Origin`: every branch of `FailureOf` (3606-3623) holds the same exception. `raisedPending` (2098) and `continuations` (2235) serve async sources and flights. `passes`, `passCount`, `passHead`, `passDrain` and `runningPasses` (2155-2167) are empty and idle unless `SchedulePass` (3037) runs, which in `Core.fs` takes an effect with `publishes` set (4753, 4766). `root` (2220) is an entry of `g_owners` at the fixed root id of Task 7. |
| `coherent` | the remarks at 530-531 | `edge_match` under the plan's name. It quantifies over every position of every observer set, so in F# it holds only for `SourceList` observers. The direct `AddObserver` sites keep a handle outside any source list: for those it rests on the simulation argument in the `ew_reachable` boundary row, and no theorem covers them. It constrains only slots holding a handle, so it implies none of `first_owns`, `slots_unique` or `held_once`. `read_without_edge` is coherent with a computation that read a source and has no edge to it, and `aba_world` is coherent with two edges for one source. `ResolveCheck` (4308) walks every slot, `None` included, and relies on a moved source marking the reader, so theorems about resolution and wake-ups need `ew_wf`, not `coherent` alone. `engine_inv` carries `ew_reachable (g_edges s)`, which gives `ew_wf` by `reachable_wf` and `ew_point` by `reachable_point`, and walks take `held_once` from `observer_held_once`. |
| `edge` | a source's `observers`, a computation's `sources` | Both ends. A slot holding `None` is no edge. `first_owns` gives that slot's source an edge from its first slot, and `coherent` does not supply `first_owns`. `edge_iff_read` is the bridge from slots to edges, under `ew_wf`. |
| `coherent_moved` | `RemoveObserverAt`, `SourceList.MovedIn` | A move occurs only inside a removal, so it is stated over `sl_remove_slot`, which also blanks the slot, as `trimFrom` does. `remove_edge` alone leaves the removed slot's handle (`remove_edge_alone_breaks_coherent`), and `sl_moved_in` alone breaks coherence (`moved_alone_breaks_coherent`). A world between `remove_edge` and the blanking is incoherent at that one slot; `trimFrom` runs no user code there. |
