# .NET DOM twin: probes, baselines and measurements

Research note for the [DOM twin spec](../superpowers/specs/2026-10-21-dom-twin-debug-dump-design.md) and its
[plan](../superpowers/plans/2026-10-21-dom-twin-debug-dump.md). Baselines were recorded on branch `feat/dom-twin` at
`691fd31`, the merge of `origin/master` at `5afc604` (#139, #140).

## Bundle baseline

`2026-10-21-dom-twin/bundle-base.json` holds the SHA-256 of `bundle.js` for the six minified `sugar-size.mjs` entries
(`explicit`, `explicit-combined`, `sugared`, `members`, `class`, `combined`), built by
`benchmarks/frameworks/bundle-hashes.mjs` from a `npm run compile:tests` output at the merge base. Gate 1 (spec §7.1)
compares each later build with it; gate 3 compares `generated-tests` with `generated-tests-base`, the Release Fable
output of `tests/DomTests.fsproj` at the same commit.

## Re-recording the bundle baseline

After a merge of `origin/master` that touches `experiments/` or `examples/Fable.Ranvier.Playground/`, the base is rebuilt
from a detached worktree of the new merge base, with its own `npm ci`:

```bash
cd C:/Users/shaya/RiderProjects/Ranvier-dom-twin
git worktree add --detach ../Ranvier-dom-twin-base $(git merge-base HEAD origin/master)
cp examples/Fable.Ranvier.Playground/benchmarks/frameworks/bundle-hashes.mjs ../Ranvier-dom-twin-base/examples/Fable.Ranvier.Playground/benchmarks/frameworks/
cd ../Ranvier-dom-twin-base/examples/Fable.Ranvier.Playground
npm ci
npm run compile:tests
node benchmarks/frameworks/bundle-hashes.mjs --out C:/Users/shaya/RiderProjects/Ranvier-dom-twin/docs/research/2026-10-21-dom-twin/bundle-base.json
rm -rf C:/Users/shaya/RiderProjects/Ranvier-dom-twin/examples/Fable.Ranvier.Playground/generated-tests-base
dotnet fable tests/DomTests.fsproj --outDir C:/Users/shaya/RiderProjects/Ranvier-dom-twin/examples/Fable.Ranvier.Playground/generated-tests-base --configuration Release
cd C:/Users/shaya/RiderProjects/Ranvier-dom-twin
git worktree remove ../Ranvier-dom-twin-base --force
```

The copied `bundle-hashes.mjs` stays untracked in the base worktree, which the last command removes.
