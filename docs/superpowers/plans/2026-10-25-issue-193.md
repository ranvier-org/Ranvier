# Issue #193: trace identity paths name the application's line

Follow-up to #166, item B1 of `docs/.ai/research/2026-10-25-issue-66.md`. Branch `issue/193`, base
`integration/issues`.

## Goal

In a traced build, `TraceSite.capture` skips frames from every Ranvier library assembly, so a node or owner
created through a library helper (`GraphHost.Start`, `Mvu`, a Ranvier.View helper) reports the application's
`file:line`. The untraced build is unchanged.

User ruling: scope is TraceSite call-site capture only. `tools/verify-trace.fsx` IL and public-surface checks
may report differences the base already has; those are reported separately from anything this change adds.

## Acceptance criteria (from the issue)

- A traced test creates nodes through `GraphHost.Start` and `Mvu` and asserts that each node's identity path
  names the test's own file.
- The same holds for a node created through a Ranvier.View helper.
- `tools/verify-trace.fsx` passes, and the untraced IL is unchanged.
- The tracing guide states which frames a path skips.

## Design

### Library marker

Every project under `src/` except the core `Ranvier` carries `AssemblyMetadata("RanvierLibrary", "true")`,
added once in `src/Directory.Build.props` with `Condition="'$(MSBuildProjectName)' != 'Ranvier'"`.

- The core keeps its reference test (`typeof<TraceEvent>.Assembly`), so the untraced `Ranvier.dll` gains no
  attribute and its IL and metadata stay byte-for-byte what the base produces.
- The marker is unconditional on `RanvierTrace` in the other libraries: a traced core used with an untraced
  `Ranvier.Elmish` package still skips Elmish frames.
- Chosen over a name list because test and sample assemblies share the prefix (`Ranvier.Tests`,
  `Ranvier.Mcp.Tests`, `Ranvier.Mcp.Sample`); a prefix match would skip the frames a path must name, and a
  closed list goes stale with each new library. Matches the existing convention of `AssemblyMetadata`
  (`RanvierTrace`) as the assembly-level switch read by `verify-trace.fsx`.

### `TraceSite.capture`

- `excluded` keeps `FSharp.Core`, `System`, `System.*`; `Ranvier` and `Ranvier.CSharp` by name become the
  marker test, with the core still matched by reference.
- Marker lookup per assembly is cached in a `ConcurrentDictionary<Assembly, bool>`
  (`Assembly.GetCustomAttributes<AssemblyMetadataAttribute>`), so a capture costs one dictionary read per frame
  after the first sight of an assembly. Traced build only.
- `inLibrarySource` extends from `src/Ranvier/` and `src/Ranvier.CSharp/` to any `src/Ranvier/`,
  `src/Ranvier.<name>/` or `src/Fable.Ranvier*/` directory, for inline helpers whose frames carry a library
  source file in the caller's assembly.
- Fable: `capture` stays null; no change.

### Risks

- Fable package sources must not pick up the generated `AssemblyInfo` file; check the packed `fable/` folder.
- A node a library creates with no application frame on the stack (a deferred library callback) reports the
  next non-library frame, as today. The guide says so.

## Steps

1. **RED: GraphHost and Mvu sites.** Traced tests: in `tests/Ranvier.Mcp.Tests`, `GraphHost.Start` with a setup
   that creates a signal and a memo in the test file; in `tests/Ranvier.Tests`, an `Mvu` created in the test
   file. Each asserts every node's (and owner's) site and identity path name the test's file. Fail on the base
   (`GraphHost.fs`, `Mvu.fs`). Commit: `test(trace): ... (#193)`.
2. **GREEN: library marker and capture.** Marker in `src/Directory.Build.props`, marker test with cache and
   extended source check in `src/Ranvier/TraceSite.fs`, doc comment updated. Step 1 passes; existing site tests
   pass. Commit: `fix(trace): skip frames from every Ranvier library assembly (#193)`.
3. **View helper site.** Traced test in `tests/Ranvier.View.Twin.Tests`: mount a view whose binding creates its
   owner and effect inside Ranvier.View; assert their sites name the test's file. Commit:
   `test(trace): Ranvier.View helper sites (#193)`.
4. **Guide.** `docs/content/guide/tracing.md` "Creation sites": the site is the innermost frame outside the
   Ranvier libraries (core and every `RanvierLibrary` assembly), FSharp.Core and `System.*`, and outside the
   libraries' inline sources; a library callback with no application frame reports the next frame. Commit:
   `docs(trace): ... (#193)`.
5. **Gate.** `build.fsx -- test` and `test-fable` (gate lock, shared); `verify-trace.fsx` on HEAD and on the
   merge base, with each failure classed as base or #193; untraced `Ranvier.dll` compared against the base build;
   packed Fable sources checked for the attribute file.
6. **Integrate.** PRIORITIES log line and Stack PR, push `issue/193`, open the PR on `integration/issues`.
